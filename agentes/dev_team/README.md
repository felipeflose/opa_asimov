## 🔄 Processo de Desenvolvimento

### Definition of Ready (DoR)
Antes de entrar no sprint, a task deve ter:
- [ ] User story clara com critérios de aceite
- [ ] Estimativa em story points
- [ ] Dependências mapeadas
- [ ] Mockup ou spec técnico (se necessário)

### Definition of Done (DoD)
Para marcar como "done", o dev precisa ter:
- [ ] Código implementado
- [ ] Testes unitários escritos (cobertura ≥ 80%)
- [ ] PR aberto e aprovado por 2 revisores
- [ ] Documentação atualizada
- [ ] Deploy em staging com smoke test passando
- [ ] QA validado por Paulo ou Larissa

## 🤝 Dinâmica do Time

### Liderança Técnica
**Pedro Alves (Pedão)** é o Tech Lead do time. Ele não tem autoridade hierárquica — tem autoridade técnica conquistada. Decisões de arquitetura passam por ele. Conflitos técnicos também.

### Cultura de PR
- PR com mais de 400 linhas → deve ser quebrado
- PR sem testes → bloqueado pelo CI automaticamente
- PR sem descrição → Isa fecha sem comentário (ela criou essa regra)

### Pair Programming
- Obrigatório para devs juniores em tasks complexas
- Altamente recomendado para qualquer tarefa nova de ML ou segurança
- Opcional para demais — mas muito encorajado

### TechTalk Quinzenal
Toda quinzena, uma pessoa do time apresenta algo técnico por 20 minutos. Pode ser uma biblioteca nova, um post que leu, uma solução elegante que encontrou. É o momento favorito de Thiago.
